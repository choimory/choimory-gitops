# README.md 작성 규칙

- 프로젝트 전체 구성과 아키텍처, 도메인 설명과 코드 내용, 구동 방법과 알아야 할 코드 규칙 등 프로젝트와 관련된 정보들을 README.md에 작성하고, 작업으로 인한 변경시에는 즉시 반영하며, 분석시에는 참고한다.
- README에 히스토리는 작성하지 않는다 - 히스토리는 git과 .agents/histories로 충분히 확인이 가능하기 때문이다
- 모든 README.md는 목차를 작성한다
- README.md를 작성할땐, 이해에 도움이 되도록 프로젝트 전체 구성이나 아키텍처, 다이어그램을 Mermaid로 같이 보여주면 좋음. (단 남용은 금물)
